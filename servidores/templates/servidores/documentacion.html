Documentacion Tecnica

Resumen del Flujo Real
  • La pantalla de Navegacion trabaja con dos modelos: Host e Instancia.
  • El autodescubrimiento soporta tomcat, node y docker.
  • El tipo de conexion define el mecanismo de escaneo y control: winrm, ssh o local.
  • El monitoreo visual funciona por SNMP o por Celery/SSH segun la configuracion guardada.
  • El monitoreo actual solo muestra datos en tiempo real; no depende de guardar metricas en la base.
Escaneo Tomcat

El endpoint de exploracion usa el tipo de conexion del host y devuelve items normalizados con nombre, estado, puerto y tipo de instalacion.

Origen Comando o script usado Que hace
WinRM Get-WmiObject Win32_Service | Where-Object { $_.Name -like '*Tomcat*' -or $_.DisplayName -like '*Tomcat*' }
Get-NetTCPConnection -State Listen | Where-Object { $_.OwningProcess -eq $pid }		 Descubre servicios Tomcat en Windows remoto y trata de asociar puertos escuchando por PID.
SSH systemctl is-active tomcat || systemctl is-active tomcat9 || systemctl is-active tomcat10
ss -ltnp | grep java || netstat -ltnp | grep java
ps aux | grep [t]omcat		 Busca servicios systemd comunes, intenta detectar puertos Java y usa procesos como fallback.
Local Get-Service | Where-Object { $_.Name -like '*Tomcat*' -or $_.DisplayName -like '*Tomcat*' }
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'java.exe' -or $_.Name -eq 'javaw.exe' }		 En Windows local detecta servicios Tomcat y procesos Java con argumentos de catalina.
El puerto HTTP se toma del item detectado; si no viene, se usa un fallback basado en puertos comunes como 8080, 80, 8181, 8081, 8000 y 3000.
Escaneo Node.js

El escaneo Node clasifica hallazgos como servicio o proceso, intenta inferir puertos y agrega metadatos como origen_node, controlable_node y rol_node.

Origen Comando o script usado Que hace
WinRM Get-WmiObject Win32_Service | Where-Object { $_.PathName -like '*node.exe*' ... }
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'node.exe' }
Get-NetTCPConnection -State Listen		 Detecta servicios Windows que ejecutan Node, procesos node.exe, puertos por PID y relaciones padre/hijo.
SSH pm2 jlist 2>/dev/null || true
systemctl list-units --type=service --all | grep -i node || true
ps aux | grep [n]ode
ss -ltnp | grep <pid> || netstat -ltnp | grep <pid>		 Descubre procesos administrados por PM2, servicios systemd y procesos sueltos, intentando elegir el puerto mas util.
Local Get-WmiObject Win32_Service | Where-Object { $_.PathName -like '*node.exe*' ... }
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'node.exe' }
Get-NetTCPConnection -State Listen		 En Windows local detecta servicios y procesos Node y trata de clasificar si parecen API o worker.
Prioridad de puertos para Node: 4000, 9005, 9007, 3000, 8080, 8000, 5000, 80 y 8888.
Escaneo y Control Docker

Docker se explora en modo local o por SSH. El flujo remoto usa sudo -S y lista tambien contenedores detenidos con -a.

Accion Comando real Descripcion
Explorar SSH sudo -S docker ps -a --format '{{.ID}}|{{.Names}}|{{.Status}}|{{.Image}}' Lista todos los contenedores remotos para agregarlos como instancias al host seleccionado.
Estado SSH sudo -S docker ps -a --filter 'name=<contenedor>' --format '{{.Status}}' Determina si un contenedor esta activo o detenido.
Control SSH sudo -S docker start|stop|restart <contenedor> Control remoto de contenedores por SSH.
Explorar Local docker ps -a --format '{{.ID}}|{{.Names}}|{{.Status}}|{{.Image}}' Lista contenedores del equipo donde corre el panel.
Puerto Local docker ps --filter 'name=<contenedor>' --format '{{.Ports}}' Intenta detectar el puerto publico de un contenedor local para corregir la verificacion HTTP.
Comandos de Verificacion y Control
Contexto Comando real Descripcion
WinRM Get-Service -Name '<servicio>' | Select-Object -ExpandProperty Status
Start-Service -InputObject $service
Stop-Service -InputObject $service -Force
Restart-Service -InputObject $service -Force		 Verifica y controla servicios Windows remotos. Cuando no hay nombre exacto usa fallback por patron *Tomcat*.
SSH systemctl is-active tomcat || systemctl is-active tomcat9 || systemctl is-active tomcat10
sudo systemctl start|stop|restart <servicio>		 Verifica y controla servicios Linux nativos.
Local Windows Get-Service -Name '<servicio>'
Start-Service -Name '<servicio>'
Stop-Service -Name '<servicio>'
Restart-Service -Name '<servicio>'
Stop-Process -Id <PID> -Force		 Servicios locales en Windows y detencion de procesos detectados por PID.
Chequeo de puerto check_tcp_port(ip, puerto) Despues de validar que el servicio esta arriba, el panel confirma si el puerto HTTP realmente responde.
Monitoreo SNMP y Celery/SSH

La ventana de monitoreo se reutiliza para SNMP y para Celery/SSH. El modo activo se controla desde Herramientas.

Modo Comando o mecanismo Descripcion
SNMP python diag_snmp.py <IP> <COMUNIDAD>
python servidores/snmp_worker.py <IP> <COMUNIDAD> [PUERTO]		 Usa un worker aislado para consultar sysDescr, sysUpTime, CPU y memoria por SNMPv2c. Si falla, la UI entra a modo simulacion.
Celery/SSH top -bn1 | grep "Cpu(s)"
free -m
pgrep -f node
pgrep -f tomcat		 La tarea Celery se conecta por SSH, extrae CPU y RAM y valida si hay procesos Node o Tomcat. Los datos se devuelven a la UI sin persistencia de metricas.
OIDs SNMP 1.3.6.1.2.1.1.1.0, 1.3.6.1.2.1.1.3.0, 1.3.6.1.2.1.25.3.3.1.2, 1.3.6.1.2.1.25.2.2.0, 1.3.6.1.4.1.2021.4.6.0 Descripcion del sistema, uptime, carga de CPU, memoria total y memoria disponible.
Para SNMP en Windows remoto normalmente se requiere abrir 161/UDP y configurar comunidad en services.msc. En Linux remoto suele bastar con instalar snmpd, definir rocommunity y reiniciar el servicio.
TrustedHosts WinRM

La seccion Herramientas usa PowerShell local para consultar y modificar TrustedHosts cuando el panel corre en Windows fuera de Docker.

Accion Comando PowerShell Descripcion
Consultar (Get-Item WSMan:\localhost\Client\TrustedHosts).Value Lee la lista actual de hosts confiables.
Agregar o fijar Set-Item WSMan:\localhost\Client\TrustedHosts -Value "host1,host2" -Force Guarda una lista explicita de hosts autorizados.
Comodin Set-Item WSMan:\localhost\Client\TrustedHosts -Value "*" -Force Permite cualquier host; util solo para pruebas.
