Documentación Técnica

Comandos Docker (Linux)

Estos comandos se ejecutan vía SSH. El usuario configurado debe tener permisos sudo.

Acción Comando Ejecutado Descripción
Buscar / Listar echo [pass] | sudo -S docker ps --format ... Lista contenedores activos con ID, nombre e imagen.
Verificar Estado echo [pass] | sudo -S docker ps --filter ... Verifica si un contenedor específico está "Up".
Iniciar echo [pass] | sudo -S docker start [nombre] Inicia un contenedor detenido.
Detener echo [pass] | sudo -S docker stop [nombre] Detiene un contenedor en ejecución.
Reiniciar echo [pass] | sudo -S docker restart [nombre] Reinicia el contenedor.
Servicios Linux (Systemd)

Para instalaciones nativas de Tomcat. Se ejecutan vía SSH.

Acción Comando Ejecutado Descripción
Verificar systemctl is-active [servicio] Consulta si el servicio está activo.
Iniciar sudo systemctl start [servicio] Arranca el servicio del sistema.
Detener sudo systemctl stop [servicio] Detiene el servicio.
Reiniciar sudo systemctl restart [servicio] Reinicia el servicio.
Monitoreo SNMP

Lectura de métricas (CPU, RAM, Uptime) usando SNMPv2c. El panel invoca un worker aislado para evitar conflictos de asyncio en Windows.

Acción Comando Ejecutado Descripción
Diagnóstico Rápido python diag_snmp.py <IP> <COMUNIDAD> Prueba GET a 1.3.6.1.2.1.1.1.0 (sysDescr) con timeout y reporte de errores.
Worker Manual python servidores/snmp_worker.py <IP> <COMUNIDAD> [PUERTO] Ejecuta el worker asíncrono que usa el panel para recolectar métricas.
Windows: Firewall New-NetFirewallRule -DisplayName \"SNMP (UDP 161)\" -Direction Inbound -Protocol UDP -LocalPort 161 -Action Allow Habilita el puerto 161/UDP en el servidor remoto.
Windows: SNMP Add-WindowsCapability -Online -Name 'SNMP.Client~~~~0.0.1.0' Instala el cliente/servicio SNMP (según edición). Configurar comunidad y hosts en services.msc.
Linux: Instalar sudo apt install snmpd && sudo systemctl restart snmpd Instala y reinicia el servicio. Configurar rocommunity en /etc/snmp/snmpd.conf.
Linux: Firewall sudo ufw allow 161/udp Abre el puerto 161/UDP en el servidor remoto.
OIDs usados: 1.3.6.1.2.1.1.1.0 (sysDescr), 1.3.6.1.2.1.1.3.0 (sysUpTime), 1.3.6.1.2.1.25.3.3.1.2 (hrProcessorLoad), 1.3.6.1.2.1.25.2.2.0 (hrMemorySize), 1.3.6.1.4.1.2021.4.6.0 (memAvailReal). Si no hay respuesta, la UI activa modo Simulación con guía de solución.
Servicios Windows (WinRM)

Comandos ejecutados vía WinRM (Remoto) usando PowerShell.

Acción Comando PowerShell Descripción
Verificar Get-Service -Name '[servicio]' Obtiene el objeto de servicio y su estado.
Iniciar Start-Service -InputObject $service Inicia el servicio de Windows.
Detener Stop-Service -InputObject $service -Force Detiene forzosamente el servicio.
Reiniciar Restart-Service -InputObject $service -Force Reinicia el servicio.
Servicios Locales (Este Equipo)

Gestión directa sobre la máquina donde corre el panel. Requiere permisos de Administrador.

Nota: Para procesos Java lanzados manualmente (IDEs), solo se permite la acción Detener usando el PID.
Contexto Comando / Lógica Descripción
Descubrimiento Get-CimInstance Win32_Process ... Busca procesos java.exe/javaw.exe con argumentos de Tomcat (catalina.base).
Servicios Win Get-Service | Where-Object ... Busca servicios instalados que contengan "Tomcat" en el nombre.
Detener PID Stop-Process -Id [PID] -Force Mata un proceso específico detectado por su ID.
WinRM TrustedHosts (Comandos)

Comandos base para consultar y establecer TrustedHosts en el cliente Windows.

Acción Comando PowerShell Descripción
Consultar (Get-Item WSMan:\localhost\Client\TrustedHosts).Value Devuelve la lista actual de hosts de confianza.
Establecer lista Set-Item WSMan:\localhost\Client\TrustedHosts -Value "10.63.17.232" -Force Reemplaza la lista con el/los hosts indicados (para varios: "host1,host2").
Activar comodín Set-Item WSMan:\localhost\Client\TrustedHosts -Value "*" -Force Permite cualquier host (no recomendado).
Para una gestión interactiva, usa la sección Herramientas en el menú.
